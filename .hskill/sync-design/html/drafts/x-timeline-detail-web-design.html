四种类型不设文字标签，靠结构本身区分：post 是无附加结构的基础卡片；reply 和 quote 都是"卡片内部结构"——回复对象是卡片内头像行之上的一行文字，被引用推文是卡片内嵌的左边框子卡片，两者都不产生任何卡片外元素；repost 是唯一的例外，因为它天然需要同时呈现两个身份（谁转推的 / 原作者是谁），只能用卡片外的浅底外框把两者分开。"卡片内部结构"和"卡片外部结构"是量级不同的两类差异，混排时不会认混。

归属反转是本稿的核心设计点：转推（repost）卡片里 author_handle 字段是被转推的原作者（示例中的 @lydiahallie），不是页面主人 @trq212 本人—— 这个信息在数据里完全不显式存在，只能靠归档文件的归属（当前浏览的 handle）推出来，所以外层框顶部保留了一行"@trq212 转推了"的说明文字（不是类型标签，是转发关系本身的必要信息，删掉这行读者就无法知道是谁转发的），内层卡片本身依然是普通白底 .tweet-card。 引用（quote）反过来：主卡片的 @trq212 就是发言人本人，被引用的 @mannay 内容降级为卡片内部的左边框嵌套小块，视觉层级上明显次于主卡片。

原文与译文（translated）默认并排显示，译文用次级文字颜色 + 虚线分隔，不用左边框——左边框留给"引用嵌套块"这一种语义，避免同一个视觉元素承担两种不同含义。 translated 为 null 时（归档未走完整 skill 流程的边界情况）这段直接不渲染，只剩原文，不显示"暂无翻译"这类占位文案。
